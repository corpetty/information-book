Complexity is the cheapest description. The laws depend on what a description may be.

This is a recap of a Lean 4 library that set out to be a unified theory of complexity, was attacked, and came back narrower and true. Everything on this page marked as proved has been checked by the machine. If the notation below is unfamiliar, start with the plain-language version; single words are explained in the glossary.

K(x) = the least cost of any description that realizes x

Choose what counts as a description, what it costs, and what "realizes" means, and you get Kolmogorov complexity, circuit size, addition chains, source coding, and more.

On its own, that definition excludes nothing: every function is K for some choice. The content appears only as the choice is restricted. Step through the restrictions below and watch which laws switch on.

    The whole thing, without the notation

    Six questions someone outside the field would ask, in the order they would ask them.

    What is being measured?

    How hard something is to describe. A million zeros make a long string with a short description: "a million zeros". A million coin flips make a string of the same length that almost certainly has no description much shorter than itself. The complexity of a thing is the size of its shortest description.

    The same question is asked in several fields under different names:

    FieldThe thingA description of itWhat it costs
    Texta string of lettersa program that prints itthe program's length in bits
    Arithmetica whole numbera chain of additions that reaches it from 1the number of additions (the library also counts the starting 1)
    Chemistrya moleculea sequence of joins, reusing parts already madethe number of joins
    Logica yes-or-no rulea circuit of simple gatesthe number of gates (the library also counts the inputs)

    In every row the answer is "the cheapest description that produces the thing". That shared shape is what the library formalizes.

    What was the ambition?

    One theory for all of those rows. State the definition once, find the laws that hold for every row (for instance: describing two things together costs no more than describing each one separately), and prove them once in Lean, a program that checks mathematical proofs line by line. Every field would then inherit the laws for free.

    What went wrong?

    The first version was reviewed with the aim of breaking it, and it broke. The definition is so general that it rules nothing out: pick any assignment of numbers to things, and some choice of "description" makes that assignment the complexity. A definition that fits everything can have no law that says anything about a particular notion of complexity.

    Eight of the claimed laws were false as stated. Five were true only because, at that generality, they said nothing. And most of the mathematics that was true had been known for decades.

    What survived?

    A map in place of a theory. Each law becomes true at some point as you tighten what a description is allowed to be, and the library now locates that point and proves a counterexample just before it. Two examples:

    Costs add up once a description must announce its own end: two such descriptions can simply be written one after the other, so a pair can always be described at the sum of the two costs. Without that, you cannot tell where the first description stops and the second begins, and the law is false.

    Complicated things are improbable (a random process rarely produces them) once all descriptions are programs for one universal machine, a machine that can imitate every other at the cost of a fixed header. For an arbitrary machine, even a computable self-delimiting one, there is a counterexample.

    A second part asks what reusing parts buys when you build things. The answers are bounds, each proved: never more than an exponential saving; nothing at all if no part repeats; always at least a logarithmic factor for large things built by stringing together a fixed stock of parts, as strings are. Several different things cap the saving, because each forces a minimum cost even with sharing: the number of distinct atoms, the depth, and a counting argument. The library proves that these three together still do not determine the cost.

    What does the machine checking buy?

    Every theorem named on this page was verified by Lean down to its basic axioms, with no gaps. That is a guarantee about the formal statement, and it is the reason the errors on this page are listed with confidence. The sentence beside each name is my summary of it. Where a summary gives a size with "about", that size is an asymptotic form read off the theorem by hand; at the worked examples the proved numbers are somewhat larger.

    It did not prevent weak statements. Five times now a theorem of mine was true for a silly reason: the object it produced could not be built at all, or the smallest case satisfied it trivially. Two of those I found by comparing results; three were found by an independent reviewer who proved the trivial versions in a few lines. It also says nothing about novelty: nearly all of this is classical, and other Lean libraries already contain much of it, sometimes in sharper form. And it says nothing about the world. Whether a real system meets a theorem's assumptions is a separate question.

    Why is this in a book about information?

    The book argues that ideas lose detail as they are retold. The formal model separates what is forced from what was assumed. Forced: a chain of retellings can pass on no more distinct versions than its tightest step allows, however long the chain. Not forced either way: whether loss grows with the number of steps. A retelling that settles after one pass loses nothing further; one that drops a little each time keeps losing. Both fit the same limits. That more steps mean more loss was an assumption of the chapter, and it is now listed as an experiment to run.

    An earlier version of this paragraph said the model shows loss depends on the tightest step and not on the number of steps. That was wrong, and a reviewer found the counterexample.

    The rest of the page goes deeper in the same order. The ladder shows where each law switches on. What sharing buys does the same for building things from parts. How we got here is the sequence of rounds, including the wrong turns. Try the objects has three small working models. The ledger lists every claim with its status. What we're after is what remains open. Any unfamiliar word should be in the glossary at the end.

    What sharing buys, law by law

    The ladder at the top narrows what a description may be. For things built from parts the question is different: what does the joining operation obey? Each row below adds one law.

    Costs count steps: bringing in a basic part, or joining two things already built. Without sharing, every part is rebuilt each time it is used. With sharing, anything built once can be reused.

    No laws

    Binary trees, built by pairing. Grouping and order both matter. Take a tree with n pairings.

    Without sharing
    2n + 1 steps, whatever the shape.Comb.binTreeK_tree
    With sharing, cheapest shape
    A perfectly balanced tree of depth d has 2^d − 1 pairings and costs d + 1 steps: an exponential saving.Comb.cost_perfect, Comb.binTreeK_perfect
    With sharing, dearest shape
    A comb costs n + 1 steps, less than half saved, and no tree costs more. In general the cost is exactly the number of different subtrees.Comb.binK_comb, Comb.cost_le, Comb.cost_eq_card_sub

    Grouping does not matter

    Strings over two letters, built by joining. Take a string of length L.

    Without sharing
    2L − 1 steps, whatever the string.Str.treeK_eq
    With sharing, cheapest strings
    One block repeated 2^k times costs k steps more than the block. No string of length L is cheaper than about log₂ L.Str.strK_pow_two_pow_le, Str.length_mul_two_le
    With sharing, dearest strings
    About L / log L, up to a constant: every string can be cut into blocks from a shared table, and most strings cannot do better.Str.strK_le_blocks, Str.card_cheap_lt

    Order does not matter either

    Products of powers of k variables, with exponents up to 2^L. The size is the total degree, as large as k · 2^L.

    Without sharing
    Twice the total degree, minus one.Binary.binTreeK_add_one_eq
    With sharing, at least
    2k − 1 steps to bring in every variable, and more than log₂ of the degree.Monomial.two_mul_le_slK_add_one, Monomial.sum_mul_two_le_two_pow
    With sharing, dearest products
    k + L + kL / log(kL), up to a constant. That is about the number of digits in the exponents, not their size.Monomial.slK_le_order, Monomial.exists_slK_gt_order

    Repeating changes nothing

    Sets, built by union. A thing joined with itself is itself. Take a set of m elements.

    Without sharing
    2m − 1 steps.
    With sharing, cheapest
    2m − 1 steps.
    With sharing, dearest
    2m − 1 steps. Sharing buys nothing, because there is nothing to repeat.SetUnion.binK_add_one_eq

    Read downward. With no laws, sharing can save almost nothing or almost everything, and the shape decides. Once grouping stops mattering, every long object must repeat short blocks, so the dearest cost drops from n to about n / log n. Once order stops mattering too, an object is just its exponents, and the cost falls to about the number of their digits. Once repeating changes nothing, size disappears and so does the saving.

    The sizes with "about" are read off the theorems by hand. None of this is new mathematics; the rows are, in order, the common subexpression problem, word chains, addition chains for vectors, and a remark.

    How we got here

    Twenty-four rounds. The second one did the most good, and three later reviews repeated it.

    1. A unified theory

      One definition, eight laws, a dozen instances from different fields, all in Lean. It claimed the laws hold "for every setting of the dials".

    2. Adversarial review

      By the author and four independent reviewers. Eight claims were false, five were true but empty, and most of the mathematics was already in the literature. The definition turned out to be a language, not a theory.

    3. Restrict until something is excluded

      Self-delimiting descriptions give a representation theorem (Kraft's inequality and its converse) and make the additive laws true. Domination is given a mechanism: one translator, constant overhead.

    4. A universal prefix machine and Levin's coding theorem

      Restricting further to computable systems produces a universal member. An online Kraft–Chaitin allocator turns "complex implies improbable" from a refuted slogan into a theorem about that machine.

    5. The reuse gap

      How much does sharing parts buy? At most an exponential; nothing when no atom repeats; at most the multiplicity of the atoms in between.

    6. An upper bound, and a conjecture that died

      Binary exponentiation attains the multiplicity bound up to a logarithm. The guess that cost is of order atoms + log multiplicity was refuted by counting, and the refutation is machine-checked.

    7. The additive laws, on one machine

      Conditional complexity K(y | x) is defined. Subadditivity, the chain rule's upper half, the two-part code and the logarithmic growth law all hold for the universal prefix machine, each up to a constant.

    8. Symmetry of information

      K(x, y) = K(x) + K(y | x, K(x)) up to a constant, in both directions. With it, typical microstates really do cost macrostate plus log W.

    9. Closing gaps, and finding company

      The functions that are prefix-machine complexities are characterized, and the two halves of micro = macro + log W are joined in one theorem. A prior-art search turned up an existing Lean 4 library that already covers much of this ground.

    10. Complexity cannot be guessed

      No bounded list of guesses contains K. So K(K(x) | x) is unbounded, and symmetry of information is false with the bare condition x: the counterexample just outside the law is now a theorem.

    11. Shared squarings, and a statement that proved nothing

      Straus's method shares the squarings among all the atoms, and brings the upper bound for monomials within a constant of the lower one when the atoms number about log m. Checking the two against each other exposed a flaw: the lower-bound theorems had allowed the empty monomial, which cannot be built at all, so they were trivially true. They now require every exponent to be at least one. A statement-by-statement comparison with the other Lean library shows that most of the universal-machine layer here is a re-proof.

    12. The worst case is the counting bound

      One construction, three times: build a shared table of everything small, then pay one step per use. For binary strings, for monomials and for Boolean circuits, the hardest object now costs what counting says it must, up to a constant.

    13. Checking the prior art, and one more overreach

      All three of those results are classical: Berstel and Brlek for strings, Straus and Pippenger for monomials, Shannon and Lupanov for circuits. The literature calls the pattern the Shannon effect. I had listed "the counting bound is always attained" as an open question; it is false, and the counterexample is now a theorem. In the free semilattice it is support that binds. And the circuit bounds turn out to be in CSLib already, in Lean, with better constants.

    14. No short list of obstructions

      Depth is a lower bound too, and growth turns out to be its shadow in a monoid. But support, depth and counting together still do not decide the cost: a bushy binary tree with one atom and logarithmic height needs almost as many steps as it has nodes, because it has that many distinct subtrees. The question I left open last round has a proved answer, and it is no.

    15. Failures that were only asserted

      Three cells of the ladder claimed a failure with no theorem behind it. They have one now: counting fails when a description may stand for many objects, the plain machine gives every object infinite probability, and the chain rule is false for plain complexity even in its easy half.

    16. A plainer account, and a wider match

      This page gained a section that explains the work without notation. The two-sided bound for monomials, which held for one shape of problem, now holds for any number of atoms between the logarithm of the exponent size and a fixed power of it.

    17. Claims that outran their proofs

      Two sentences on this page said more than had been proved. "In a tree the cost is the number of distinct subtrees" had only "at least" behind it; it is now an equality. "Most strings gain only a logarithm" had only one such string behind it; it now has a count.

    18. Monomials, every shape

      Grouping the atoms works when exponents are long. Grouping the binary digits of the exponents works when atoms are many. With both, the bounds on the hardest monomial meet up to a constant for every number of atoms and every exponent size. At first the comparison was done by hand; it is now four theorems with explicit constants.

    19. A second adversarial review

      A reviewer with no stake in the work compared each sentence on this page with the theorem it cites. Three theorems were true for a trivial reason and are restated. One heading was false: additive size does not guarantee a logarithmic gain, associativity does. Two ladder cells cited a result for a different class or a different formula. All are corrected, and the page now says which sizes are theorems and which are read off by hand.

    20. A third review, of the older claims

      The same kind of reviewer went through the first six sections. Two claims were false as worded. One matters to the book: the model does not show that loss is set by the tightest hop; a relay that leaks a bit per retelling fits it too. The other: the plain universal machine dominates more than the computable methods, not exactly those. The refutation of "complex implies improbable" used a different toy system for each constant; it now uses one system. First-version slogans still sitting in the source files were retired.

    21. Words for everyone

      This page gained a glossary of 74 terms in plain language, so that a reader who has never met Kolmogorov complexity, a straight-line program or a proof assistant can follow the rest.

    22. The defect is small

      Symmetry of information fails when the condition is the bare object. A chain rule for conditional complexity shows it fails by no more than a logarithm of the object's own complexity. The counterexample just outside the law now has a size, from both sides.

    23. A review of the plain-language text

      A reviewer checked the explainer, the glossary and the demos against the theorems. One sentence was wrong: what makes complicated things improbable is not that there is one fixed machine but that the machine is universal. Others had a direction reversed, or defined a word by its best-known example. The reviewer also found that the other Lean library does treat general description relations, which this page had listed as not found. All corrected.

    24. A second ladder

      The reuse results were a list. They are now arranged by what the joining operation obeys: no laws, then grouping, then order, then repetition. One small theorem was missing for it, the cost of a perfect tree without sharing.

    Try the objects

    Three small machines from the library, runnable here. Each one is the idea behind a theorem.

    The temperature dial

    An object with eight self-delimiting descriptions of various lengths. Weigh each description by q raised to its length and add them up: that sum is Z(q). One dial takes you from complexity, through probability, to plain counting.

    q, the weight per bit
    Z(q), the total weight
    Share carried by the shortest description

    In the library: Thermo.pow_le_Z_of_K_le (simple implies probable) holds for every system. The converse does not: it needed the universal prefix machine and Levin's theorem.

    The Kraft–Chaitin allocator

    Ask for codewords one at a time. A request of length n claims a slice of width 2−n of the unit interval and receives a codeword of length n + 1: the aligned half-slice that fits inside it. No codeword is ever a prefix of another, and nothing has to be planned ahead.

      In the library: KraftChaitin.exists_machine. The same decoder, fed Levin's requests, proves the coding theorem; fed those requests rescaled for each condition, it proves symmetry of information.

      What reuse buys

      Build a product of k different atoms, each repeated m times. Without sharing, every copy is paid for. With sharing, a power is built by squaring and each intermediate result is paid for once.

      Gain from sharing, binary method
      Proved ceiling on the gain

      In the library: MonoidGen.slK_pow_le, Monomial.slK_add_one_le, Binary.gain_le_multiplicity. Set m to 1 and the gain disappears: when nothing repeats, reuse buys nothing (Binary.binK_eq_binTreeK_of_le). The gain shown is for the binary method, so it is a lower estimate of the best possible gain.

        What we're after

        The original aim was one theory of complexity across fields. The review showed that the shared definition is only a common language. The aim that survived is sharper: for each law, find the weakest restriction on descriptions under which it holds, and prove a counterexample just outside it.

        For the information-theoretic laws that classification is now nearly complete, as the ladder shows: every stage has a representation theorem, and every law has a stage where it holds. For reuse it is partial. These are the gaps.

        One standing caveat. Almost every result here is classical in the field it comes from. What the library adds is one counting lemma and one set of reuse lemmas from which the circuit, addition-chain and string bounds all follow, a map of which law holds under which restriction, and machine-checked proofs of where each fails. It is also not the first formalization. A Lean 4 library covering much of the same ground on prefix complexity already exists; it obtains plain and prefix complexity by restricting a general relation between descriptions and objects, and it has a stronger form of one of the counterexamples here. CSLib has the circuit bounds of Shannon and Lupanov with better constants. The ladder of representation theorems, most of the proved counterexamples, and the worst-case bounds for strings and monomials were not found formalized elsewhere, but the searches were short.

        Words used here

        74 terms, in plain language. Definitions are the working meaning on this page, not the full technical one.

        The basic idea

        Complexity
        Here, the size of the shortest description of a thing. It is not the same as looking complicated: a huge but regular object, like a million zeros, has low complexity.
        Description
        Anything that, by the rules in force, stands for an object. A program that prints a text, a recipe of joins for a molecule and a circuit for a yes-or-no rule are all descriptions. In the most general setting one description may stand for several objects; requiring that it stand for at most one is the first restriction.
        Cost
        The size of a description, in whatever unit the field counts: bits for programs, steps for constructions, gates for circuits.
        Realizes
        A description realizes an object when following it produces that object.
        Description system
        A choice of three things: what counts as a description, what each one costs, and which object each one realizes. Every statement in the library is relative to such a choice.
        K(x)
        The complexity of x: the least cost of any description that realizes x. If nothing realizes x, the complexity is infinite.
        Law
        A general statement about complexity that is meant to hold for a whole class of description systems. Example: describing two things together costs no more than describing each one separately.
        Restriction
        A rule that narrows what counts as a description, such as "a description must announce its own end". The library tracks which laws become true under which restrictions.
        The ladder
        This page's name for four nested classes of description systems, from "anything at all" down to "programs for one universal machine". Each step down is a restriction.

        Bits, programs and machines

        Bit, bit string
        A bit is one yes-or-no choice, written 0 or 1. A bit string is a row of them. Lengths of descriptions are counted in bits.
        Unambiguous
        Each description realizes at most one object. Without this, one description could stand for everything and counting would mean nothing.
        Self-delimiting
        No description is the beginning of another one, so a reader knows where a description ends without being told. Phone numbers work this way: no complete number is the start of a longer one. Also called prefix-free.
        Kraft's inequality
        The budget rule for self-delimiting descriptions. Give each description of length n a weight of one half to the power n; the weights can add up to at most 1. Short descriptions are scarce.
        Machine, program
        A machine is a fixed mechanical rule that turns an input string into an output. A program is an input for it.
        Computable
        Producible by a program that follows mechanical steps and eventually stops.
        Universal machine
        One machine that can imitate any other, given a fixed header that says which one. Complexity measured on it is, up to a constant, as small as on any machine.
        Kolmogorov complexity
        The length of the shortest program that prints an object on a universal machine. Named after Andrey Kolmogorov.
        Plain complexity
        Kolmogorov complexity with no requirement that programs be self-delimiting. Often written C. Several additive laws are false for it.
        Prefix complexity
        Kolmogorov complexity on a universal machine whose programs are self-delimiting. Often written K. This is the version for which costs add up properly.
        Up to a constant
        True after adding one fixed number that does not depend on the objects involved. Changing from one universal machine to another changes complexities by at most such a number.
        Invariance
        The fact that any two universal machines assign complexities that differ by at most a constant. It is what makes "the" complexity of an object meaningful.
        Domination
        One description system dominates another when its complexities are never larger than the other's plus a constant.
        Incompressible
        Having no description much shorter than the object itself. Most objects are incompressible, because there are too few short descriptions to go round.
        Counting law
        There cannot be more cheap objects than cheap descriptions. With bit strings: fewer than 2 to the power n objects have complexity below n.
        Subadditivity
        Describing two things together costs at most the sum of describing each, plus a constant.
        Conditional complexity
        The length of the shortest program that produces y when it is handed x for free. Written K(y | x).
        x*
        The object x together with its own complexity K(x). It carries slightly more information than x alone, because K(x) cannot be worked out from x.
        Chain rule
        The cost of a pair is the cost of the first plus the cost of the second given the first. For prefix complexity it holds up to a constant when "given the first" means given x*.
        Symmetry of information
        The chain rule read both ways: what x tells you about y is as much as what y tells you about x, up to a constant.
        Algorithmic probability
        The chance that a machine fed random coin flips as its program prints x.
        Coding theorem
        For the universal self-delimiting machine, the algorithmic probability of x is one half to the power K(x), up to a constant factor. Simple things are likely and complex things are unlikely. Due to Leonid Levin.
        Not computable
        No program works out K(x) for every x. The library proves more: no program can even list a fixed number of guesses that always include the right value.
        Approximable from above
        There is a mechanical procedure that produces better and better upper estimates and eventually reaches the true value, but may never announce that it has. Every computable quantity is like this; K is like this without being computable.
        Macrostate, microstate
        A macrostate is a group of similar objects; a microstate is one member. A two-part description names the group, then says which member: the cost of the group plus the logarithm of its size.
        Growth law
        Running a fixed computable rule for t steps adds at most the cost of writing down t in self-delimiting form: about twice the logarithm of t, in the form proved here.

        Building things from parts

        Generator, atom
        A basic part that is given at the start: a letter, a variable, the number 1.
        Operation, join
        The way two things already built are combined into a new one: concatenating strings, multiplying, wiring a gate.
        Step
        Introducing one generator, or applying the operation once.
        Cost without sharing
        The number of steps if every part must be rebuilt each time it is used. For circuits this is formula size. Also called tree cost.
        Cost with sharing
        The number of steps if anything built once may be reused freely. For circuits this is circuit size; for numbers, one more than the length of the shortest addition chain, because the library counts the starting 1 as a step.
        Straight-line program
        A list of steps with no loops, each using results of earlier steps. The length of the shortest one is the cost with sharing.
        Addition chain
        A way to reach a number from 1 where each new number is the sum of two earlier ones. Reaching 16 takes four doublings.
        Monomial, exponent
        A monomial is a product of variables raised to whole-number powers, like x squared times y to the fifth. The powers are the exponents; the variables are its atoms.
        Boolean function
        A yes-or-no rule that depends on several yes-or-no inputs.
        Circuit, gate, NAND
        A circuit computes a Boolean function by wiring simple gates together. NAND is a gate that says no only when both inputs say yes; every Boolean function can be built from it.
        Monoid
        A setting where combining is associative: grouping does not matter, as with joining strings or multiplying. This is what allows a long product to be cut into blocks.
        Binary tree
        A shape built by pairing, where grouping does matter. A comb is one long spine; a perfect tree is fully balanced; the bush in the library's counterexample is a balanced tree with a different chain at each tip.
        Lower bound, upper bound
        A lower bound says every way of building the thing needs at least this many steps. An upper bound says this many always suffice.
        Support bound
        Every distinct atom must be brought in at least once, and joined to the rest: m atoms need 2m − 1 steps.
        Depth bound
        A construction cannot be shallower than the object is deep. The growth bound is a special case: if size can at most double per step, a thing of size n needs about log₂ n steps.
        Counting bound
        With few steps only few different things can be built, so in a large population some member needs many steps.
        Distinct parts
        In binary trees the cost with sharing is exactly the number of different subtrees; that is proved here. The same is expected wherever nothing is equal by accident.
        Shared table
        The idea behind the upper bounds here: build everything small once, then pay one step each time an entry is used.
        Shannon effect
        The hardest object in a class costs about as much as almost every object in it.
        Logarithm
        log₂ n is the number of doublings needed to get from 1 to n. It grows very slowly: the logarithm of a million is about 20.
        Exponential
        Growing by a fixed factor at every step, such as doubling. Twenty doublings reach a million.
        Up to a constant factor
        Two quantities whose ratio stays between two fixed numbers however large the objects get. Also said as "of the same order".

        Proof, checking and review

        Lean
        A programming language in which mathematical statements and their proofs are written out so that a program can check every step.
        Formalize
        To write a statement and its proof in such a language.
        Theorem, proved
        A statement the checker has verified. The names in monospace on this page are the identifiers of theorems in the library.
        Axiom audit
        Axioms are the starting assumptions. The audit confirms that every theorem in the library rests only on Lean's three standard ones, with no gaps left to fill.
        Counterexample
        One specific case that shows a general claim is false.
        Conjecture
        A statement someone believes but has not proved.
        Refuted
        Shown to be false. On this page that means a machine-checked counterexample exists.
        Empty statement
        A statement that is true only because it says nothing, for instance because an object that cannot be built satisfies it. Also called vacuous.
        Degenerate witness
        The junk example that makes a "there exists" statement true for a silly reason.
        Adversarial review
        A review whose aim is to break the claims, not to confirm them.
        Prior art
        What was already known or already done by others. Nearly all the mathematics here is.
        About, asymptotic
        A size given with "about" describes what happens for large objects. At small sizes the exact proved numbers can be noticeably larger.

        The book's model of retelling

        Relay
        A person or step that receives an idea and passes on a version of it.
        Budget
        The largest number of bits a relay's message may use.
        Hop, chain
        A hop is one passing-on. A chain is a sequence of relays, each receiving what the last one sent.
        Bottleneck
        The tightest budget along a chain. It caps how many different versions can come out the far end, however long the chain is.
        Stable relay, leaking relay
        A stable relay, retold through itself, changes nothing further after the first pass. A leaking relay drops a little more each time. Both respect the same budget.
